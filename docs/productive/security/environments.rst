Separating environments
=======================

Current best practice is to separate different environments depending on what is
to be done in each one. For example, in our `cusy.tasks
<https://github.com/cusyio/cusy.tasks>`_ application, a distinction is made
between the following environments:

.. code-block:: toml
   :caption: pyproject.toml

   [project]

   dependencies = [
     "rich",
     "tinydb",
     "typer",
   ]

   [dependency-groups]
   dev = [
     "pre-commit",
     "reuse",
     "tox-uv",
     "watchgha",
     { include-group = "docs" },
     { include-group = "tests" },
   ]
   docs = [
     "furo",
     "interrogate",
     "matplotlib",
     "sphinx-copybutton",
     "sphinx-inline-tabs",
     "sphinxcontrib-napoleon",
     "sphinxext-opengraph",
   ]
   tests = [
     "coverage[toml]",
     "faker",
     "pytest",
     "pytest-cov",
   ]

This means that when the application is running, only the dependencies required
for that purpose are installed; additional dependencies are only installed when
testing or deploying the documentation. Only the development environment
contains all dependencies.

Just as your Python environment should be kept up to date with immutable
references, your :doc:`../git/advanced/hooks/checks` and GitHub Actions should
also be updated regularly.

In the :file:`.pre-commit-config.yaml` file, the versions of the checks and
their hashes should be updated regularly, for example using:

.. code-block:: console

   $ uv run prek update --freeze --cooldown-days 7
   https://github.com/pre-commit/pre-commit-hooks
     updating rev `v6.0.0` -> `3e8a8703264a2f4a69428a0aa4dcb512790b2c8c` (frozen: v6.0.0)

.. seealso::
   :doc:`../git/advanced/hooks/prek`

Check your GitHub Actions
-------------------------

As GitHub Actions are retrieved from :doc:`Git <../git/index>`, it is
recommended that you specify a full SHA rather than a tag, as tags can be
altered and are vulnerable to supply-chain attacks.

.. _pinact:

pinact
~~~~~~

For GitHub Actions, you can use `pinact
<https://github.com/suzuki-shunsuke/pinact>`_, for example with:

.. code-block:: console

   $ pinact run --update --min-age 7

This updates the GitHub Actions, but with a seven-day cooldown.

.. _gh-actions-lock:

gh-actions-lock
~~~~~~~~~~~~~~~

`gh-actions-lock
<https://github.com/github/gh-actions-lock#install>`_ goes a bit further and
also records the transitive links in the :file:`.github/workflows/actions.lock`
file. You can install ``gh-actions-lock`` using `GitHub CLI
<https://cli.github.com/>`_:

.. code-block:: console

   $ gh extension install github/gh-actions-lock
   ✓ Installed extension github/gh-actions-lock

You can then lock your GitHub Actions in your repository using

.. code-block:: console

   gh actions-lock

   ✓ Pinned 7 actions (+ 3 transitive) across 3 workflows
       actions/checkout@v7.0.1 (3d3c42e)
         └─ .github/workflows/docs.yml
         └─ .github/workflows/prek.yml
         └─ .github/workflows/zizmor.yml
       pandoc/actions@v1.1.1 (86321b6)
         └─ .github/workflows/docs.yml
       ts-graphviz/setup-graphviz@v2.0.2 (b1de5da)
         └─ .github/workflows/docs.yml
       actions/setup-python@v7.0.0 (5fda3b9)
         └─ .github/workflows/docs.yml
       hynek/setup-cached-uv@v2.6.0 (34e35d3)
         └─ .github/workflows/docs.yml

         └─ .github/workflows/prek.yml
       zizmorcore/zizmor-action@v0.6.4 (cc914d7)
         └─ .github/workflows/zizmor.yml

       actions/cache@55cc834 via hynek/setup-cached-uv@v2.6.0

       github/codeql-action@cdf488f via zizmorcore/zizmor-action@v0.6.4

The :file:`.github/workflows/actions.lock` will then begin with:

.. code-block:: yaml

   # This file is machine-generated by `gh actions-lock`.
   # Do not edit by hand; run `gh actions-lock` to update.
   # Docs: https://gh.io/actions-lockfile
   version: 'v0.0.3'
   workflows:
       '.github/workflows/docs.yml':
           - 'actions/checkout@v7.0.1'
           - 'actions/setup-python@v7.0.0'
           - 'hynek/setup-cached-uv@v2.6.0'
           - 'pandoc/actions@v1.1.1'
           - 'ts-graphviz/setup-graphviz@v2.0.2'
       '.github/workflows/prek.yml':
           - 'actions/checkout@v7.0.1'
           - 'j178/prek-action@v3.0.0'
       '.github/workflows/zizmor.yml':

GitHub also recommends `checking lock files as part of the CI process
<https://docs.github.com/de/actions/how-tos/administer/enforce-workflow-lockfiles#a-dedicated-workflow-or-copilot>`_
to ensure that they are up to date and not corrupted. To do this, we create
:file:`.github/workflows/verify-lockfile.yml` with:

.. code-block:: yaml

   # Fails when .github/workflows/actions.lock is out of sync with the
   # workflows or a locked pin no longer verifies upstream.
   lockfile:
     runs-on: ubuntu-slim
     env:
       GH_TOKEN: ${{ github.token }}

     steps:
       - uses: actions/checkout@v7.0.1
         with:
           persist-credentials: false
       - run: gh extension install github/gh-actions-lock --pin v0.4.1
       - run: gh actions-lock --verify

.. seealso::
   * `GitHub Actions workflow lockfiles are generally available
     <https://github.blog/changelog/2026-10-28-github-actions-workflow-lockfiles-are-generally-available/>`_
   * :doc:`../envs/uv/renovate` also supports
     :file:`.github/workflows/actions.lock` files:
     `Renovate CLI documentation
     <https://docs.renovatebot.com/modules/manager/github-actions/#github-actions-lockfile-actionslock>`_.

zizmor
~~~~~~

`zizmor <https://docs.zizmor.sh>`_ is a static analysis tool that detects
security vulnerabilities in GitHub Actions workflows – including template
injection, unpinned actions, excessive permissions, credential exposure and
`more than 30 other checks <https://docs.zizmor.sh/audits/>`_. zizmor identifies
vulnerabilities such as those exploited through :ref:`token exfiltration
<token-exfiltration>`.

You can also use zizmor together with :doc:`../git/advanced/hooks/prek`:

.. code-block:: yaml

   - repo: https://github.com/zizmorcore/zizmor-pre-commit
     rev: 06a39750ec31860bb44f2acf67182c40016cd1e7  # frozen: v1.32.0
     hooks:
       - id: zizmor

   * :ref:`zizmorcore`
